[left][color=#ffffff][size=6][b]SnapOpen[/b][/size][/color][/left]
[i][size=4]Doors and containers open (almost) instantly. No mesh edits, no animation replacers, nothing to fight with your other mods for the same files.[/size][/i]

[img width=640](add a screenshot or, better, a short gif of a door/chest snapping open here)[/img]

[size=4][b]How it works[/b][/size]
[list]
[*]Speeds up the actual opening animation for doors and containers, so it plays out in a fraction of a second instead of the usual second-plus creak.[/*]
[*]Only touches doors that actually load into a new cell - a "double door" or other same-room prop stays untouched, exactly as vanilla.[/*]
[*]Optionally also trims several Skyrim.ini loading-screen fade durations (door fades, save-load fades, fast travel), so the whole transition feels snappier, not just the animation.[/*]
[*]Everything is set via a plain .ini file next to the plugin, sensible defaults out of the box.[/*]
[/list]

[color=#008000][b]Safe to install, update, or remove at any point in a playthrough - it's stateless: no new records, no scripts, nothing written to your save.[/b][/color]

[size=4][b]Installation[/b][/size]
Install with your mod manager like any other SKSE plugin. Requires:
[list]
[*][url=https://www.nexusmods.com/skyrimspecialedition/mods/32444]Address Library for SKSE Plugins[/url], matching your game version[/*]
[*][url=https://skse.silverlock.org/]SKSE64[/url][/list]
Works on both Skyrim SE/AE 1.6.1170 and 1.7.104 from the same download - no separate version to pick.

[b][size=4]Configuration[/size][/b]
[font=Courier New]SnapOpen.ini[/font] (next to the plugin, under SKSE/Plugins) has two settings:
[list]
[*][font=Courier New]bOverrideFadeSettings[/font] : also shortens the Skyrim.ini fade/loading durations mentioned above. Set to 0 to leave your own Skyrim.ini alone. On by default.[/*]
[*][font=Courier New]bExperimentalNPCDoors[/font] : also speeds up doors when NPCs use them, not just you. Off by default - untested for side effects on AI/scripts that expect the door to take a moment.[/*]
[/list]
The animation/fade speeds themselves aren't configurable on purpose - they're tuned to feel instant without skipping any sound or script cues, and exposing them felt more likely to cause "why is this glitchy" reports than to help anyone.

[b][size=4]But... why?[/size][/b]
The existing solutions for this are mostly mesh/behavior edits, which work but turn into a constant source of conflicts with anything else touching the same doors or containers. Doing it in code instead means it just works alongside whatever else you've got installed. This was also my first real C++/SKSE plugin - wanted to actually learn how CommonLibSSE-NG works under the hood rather than just installing other people's mods.

[b][size=4]Known issues and limitations[/size][/b]
[list]
[*]Doesn't touch the container/inventory menu's own opening animation (that's Scaleform/Flash UI, not something this kind of plugin can reach) or the book-reading animation (a whole separate Havok behavior graph). If those bother you too, look for a UI overhaul for the former and there are dedicated mods for the latter.[/*]
[*]bExperimentalNPCDoors is exactly that - experimental. Report anything weird you see with it on.[/*]
[/list]
